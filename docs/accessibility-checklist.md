# 접근성 점검 체크리스트 (셸 화면용)

기능을 완성한 뒤 이 목록으로 점검한다. 자동 검사 도구는 전체 문제의 30~40%만
잡아내므로, **키보드 실사용 점검과 스크린리더 실사용 점검은 생략할 수 없다.**

## 1. 키보드만으로 완주

마우스를 치우고 Tab / Shift+Tab / Enter / Space / 방향키만 사용한다.

- [ ] 첫 Tab 에서 "본문으로 건너뛰기" 링크가 화면에 나타난다
- [ ] Tab 으로 모든 인터랙티브 요소에 도달한다 (빠지는 것이 없다)
- [ ] Tab 순서가 화면에 보이는 순서와 같다
- [ ] 지금 어디에 포커스가 있는지 항상 눈으로 알 수 있다
- [ ] 포커스가 화면 밖으로 나가지 않는다 (스크롤이 따라온다)
- [ ] 체크박스: Space 로 켜고 끈다
- [ ] 라디오: 방향키로 선택이 이동한다. Tab 은 그룹 전체를 한 번만 지난다
- [ ] "자세히 보기": Enter 또는 Space 로 펼치고 접는다
- [ ] 포커스가 어디에도 갇히지 않는다 (키보드 트랩 없음)
- [ ] 제출 실패 시 포커스가 오류 요약으로 이동한다
- [ ] 오류 요약의 링크를 Enter 로 누르면 해당 입력란에 포커스가 잡힌다

## 2. 스크린리더

NVDA(Windows) 기준. 가능하면 JAWS, VoiceOver 도 확인.

- [ ] 페이지 진입 시 페이지 제목이 읽힌다
- [ ] 제목 단축키(H)로 h1 → h2 → h3 위계를 훑을 수 있다. 단계가 건너뛰지 않는다
- [ ] 폼 요소 단축키(F)로 훑을 때 각 요소의 이름이 무엇인지 알 수 있다
- [ ] 체크박스마다 "필수" 표시와 항목 이름이 함께 읽힌다
- [ ] 체크박스의 한 줄 요약이 설명으로 읽힌다
- [ ] "자세히 보기"가 어느 항목의 상세인지 구분되어 읽힌다
      (같은 이름의 버튼 4개로 들리면 실패)
- [ ] 접힌 상세 내용은 접근성 트리에서 제외된다 (접힌 상태로 훑을 때 안 읽힘)
- [ ] 제출 실패 시 오류 요약 내용이 읽힌다
- [ ] 오류가 있는 입력란에 포커스하면 오류 메시지가 함께 읽힌다
- [ ] 화면 전환(1단계 → 2단계) 후 새 화면 제목이 읽힌다

## 3. 저시력 시인성 (스크린리더와 동등한 우선순위)

**대비** — 손계산을 믿지 말고 브라우저에서 실측한다. 라이트·다크 양쪽 모두.

- [ ] 본문 텍스트 대비 4.5:1 이상 (최소선), **7:1 이상 (지향선)**
- [ ] 보조·muted 텍스트도 같은 기준을 만족한다 (작고 흐린 글씨가 가장 위험하다)
- [ ] 체크박스·입력란 테두리, 포커스 링 대비 3:1 이상
- [ ] `tokens.css` 주석의 대비 수치가 실측값과 일치한다
- [ ] 색을 제거해도(흑백 출력) 필수/선택, 민감정보, 오류 여부를 구분할 수 있다
      — 아이콘·텍스트·패턴이 색과 함께 쓰였는지 확인

**글자 크기·굵기**

- [ ] 본문 20px, 보조 텍스트 18px 이상. **16px 미만 글자가 화면에 없다**
- [ ] 크기가 전부 rem 이다 (px 고정값 없음)
- [ ] Pretendard 가 실제로 적용됐다 (폴백 서체로 렌더링되고 있지 않은지 확인)
- [ ] 어떤 텍스트도 Light/Thin(100~300) 으로 렌더링되지 않는다
- [ ] 자간이 음수인 요소가 없다
- [ ] 브라우저 글자 크기만 200% 로 키워도 내용이 잘리지 않는다
- [ ] 브라우저 확대 400% 에서 가로 스크롤이 생기지 않는다

**그 외 시각**

- [ ] Windows 고대비 모드에서 체크 상태, 포커스, 버튼 경계가 보인다
- [ ] OS 다크 모드에서 모든 텍스트가 읽힌다
- [ ] 클릭·터치 타겟이 44×44px 이상이다
- [ ] `prefers-reduced-motion` 을 켜면 펼침 애니메이션이 사라진다

## 3.5 폼 화면 공통 (기본정보·장애정보·기기사양)

**조건부 노출 입력란** (성별 직접입력, 기타, 보조기기, 장애 정도, 좌우 방향)

- [ ] 트리거를 선택하면 그 **바로 다음 Tab** 이 새 입력란으로 들어간다
- [ ] 선택 시 포커스를 강제로 빼앗지 않는다 (라디오를 방향키로 훑는 중이면
      다른 선택지를 확인할 수 없게 된다)
- [ ] 등장 사실이 라이브 리전으로 1회 안내된다
- [ ] 선택을 해제하면 입력란과 **저장된 값이 함께 사라진다**
      (남으면 CSV 에 유령 값이 실린다)

**반복 폼** (부가 기기)

- [ ] "기기 추가" 후 포커스가 **새 입력란**으로 이동한다
- [ ] 삭제 후 포커스가 **"기기 추가" 버튼**으로 이동한다 (body 로 튕기면 실패)
- [ ] 삭제 버튼 이름에 번호가 들어가 여러 개일 때 구분된다
- [ ] 중간 항목을 삭제해도 **뒤 항목의 값이 밀리지 않는다** (고정 id)
- [ ] 항목 추가·삭제가 라이브 리전으로 안내된다

**실시간 검증** (고유 ID)

- [ ] 타이핑 중 미완성 값에 오류를 띄우지 않는다 (`GA11Y-P` 에서 빨간 테두리 금지)
- [ ] 완성될 수 없는 값(`GA11X` 등)은 즉시 오류로 표시된다
- [ ] 소문자로 입력해도 대문자로 바뀌고 **캐럿 위치가 튀지 않는다**
- [ ] 검증 문구가 라이브 리전이 아니다 (한 글자마다 낭독이 끼어들면 실패)
- [ ] "유효해진 순간"만 1회 안내된다

**확인 방법 안내 (캡션)**

- [ ] 호버 툴팁이 아니라 **항상 보이는 텍스트**다
- [ ] 마우스 없이도, 스크린리더로도 같은 내용에 도달한다

**배타 선택**

- [ ] "사용 안 함"을 고르면 다른 항목이 해제된다
- [ ] 다른 항목을 고르면 "사용 안 함"이 해제된다

## 4. 자동 검사 (보조 수단)

- [ ] axe DevTools 또는 WAVE 에서 위반 0건
- [ ] HTML 유효성 검사 통과 (중복 id 없음, 라벨 없는 입력 없음)
- [ ] 브라우저 콘솔 경고 없음

## 5. 개인정보 절차 점검 (이 프로젝트 고유)

- [ ] 동의 전 상태에서 개발자 도구로 DOM 을 검색해도 참여자 정보 입력 필드가
      존재하지 않는다
- [ ] 동의 항목 4건 중 하나라도 미동의면 다음 단계로 넘어가지 않는다
- [ ] `CONSENT_VERSION` 을 올리면 기존 저장된 동의가 무효화되고 재동의를 받는다
- [ ] `SESSION_SCHEMA_VERSION` 을 올리면 저장된 초안이 무효화된다
- [ ] **동의 항목이 전부 false 인 기록을 localStorage 에 넣어도 게이트를 통과하지
      못한다** (버전만 검사하고 items 를 안 보면 우회된다 — 실제로 발생했던 결함)
- [ ] 일부 항목만 true 인 기록, items 가 누락된 기록도 무효 처리된다
- [ ] 진행 로그에 개인정보 값 자체가 들어 있지 않다 (무엇이 저장됐는지만)
- [ ] `⚠️ 확정 필요` 문구가 화면에 남아 있지 않다 (배포 전 필수)
- [ ] `src/devFlags.ts` 가 삭제됐거나 `STEP_BACK_NAV` 가 false 다 (배포 전 필수)
- [ ] 동의 화면의 체크박스가 **미리 체크된 채로 나타나지 않는다**

## 6. 경로 분기 점검 (장애 정보 1단계)

- [ ] 등록 여부에 답하기 전에는 **어느 쪽 질문도 화면에 없다**
- [ ] 갈림길을 고르면 그 사실이 라이브 리전으로 1회 안내된다
- [ ] 경로를 바꾸면 반대편 경로의 값과 2단계 양상이 **함께 지워진다**
      (남으면 화면에 보이지 않는 값이 CSV 로 나간다)
- [ ] 미등록자 경로에서 "해당 없음"을 고르면 다른 영역이 해제되고 2단계가 빈다
- [ ] 오류 요약의 링크가 **현재 화면에 있는 요소**만 가리킨다
      (보이지 않는 갈래의 항목을 가리키면 눌러도 갈 곳이 없다)
