# game-a11y-fundamental-test — 시스템 A

장애인 게이머의 게임 플레이 기초 역량 측정 **참여자용 웹페이지**.

이 저장소는 참여자가 직접 쓰는 부분(시스템 A)만 담습니다. 관리자용 리포트·영상
분석 도구(시스템 B)는 **별도 저장소**에서 개발하며 공개 배포하지 않습니다.

참여자 흐름: 동의 → 기본정보 → 장애정보 → 기기사양 → 역량 테스트 →
**결과 CSV 다운로드 → 이메일 제출**. 서버로 전송되는 정보는 없습니다.

- 전체 기획·로드맵: [SYSTEM_SPEC.md](SYSTEM_SPEC.md)
- 개발 규칙·접근성 원칙: [CLAUDE.md](CLAUDE.md)
- 접근성 점검 체크리스트: [docs/accessibility-checklist.md](docs/accessibility-checklist.md)

## 사전 준비

Node.js 18 이상이 필요합니다. 설치되어 있지 않다면:

```bash
winget install OpenJS.NodeJS.LTS
```

설치 후 **터미널(또는 에디터)을 새로 열어야** `node`, `npm` 명령이 인식됩니다.
설치 시점에 이미 열려 있던 프로세스는 갱신 전 PATH를 그대로 물고 있습니다.

검증된 조합: **Node 24.19.0 / npm 11.17.0**

## 실행

```bash
npm install
npm run dev
```

npm 11 이상은 의존성의 설치 스크립트를 기본 차단합니다. Vite 빌드에 필요한
esbuild가 차단됐다는 경고가 나오면 한 번 승인해 주세요.

```bash
npm approve-scripts esbuild
```

터미널에 표시되는 주소(기본 `http://localhost:5173`)를 브라우저에서 엽니다.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 프로덕션 빌드 (`dist/`) |
| `npm run preview` | 빌드 결과 확인 (배포본과 동일) |
| `npm run deploy` | 로컬 빌드 → `gh-pages` 브랜치 푸시 |

## 현재 구현 범위

**1단계 — 개인정보 수집·이용 동의 화면** (`src/screens/consent/`)

- 필수 4건 — A 일반 개인정보 / B 민감정보(별도 동의) / C 테스트 응답·결과 /
  E 비식별 데이터의 학술·통계 활용. 선택 항목은 없다
- 항목별 "자세히 보기" 접기/펼치기
- 입력한 정보가 어떻게 전달되는지(서버 미전송 → CSV 이메일 제출) 고지
- 한 항목이라도 미동의 시 다음 단계 차단 + 오류 요약으로 포커스 이동

**2단계 — 참여자 기본정보** (`src/screens/basicInfo/`) — SYSTEM_SPEC 3-2

- 고유 ID 단일 입력 + 실시간 정규식 검증 (소문자 자동 대문자 변환)
- 성별(직접 입력 시 자유 텍스트), 연령대, 참여 경로(기타 시 자유 텍스트),
  게임 경력, 선호 장르(다중), 주간 플레이 시간,
  보조기기 사용 여부(예 시 명칭 입력), 접근성 기능(다중, "사용 안 함" 배타)
- 모든 선택지는 라디오/체크박스 (드롭다운 미사용 — 이유는 SYSTEM_SPEC 3-2 주석)
- ID 경로코드와 참여 경로 불일치 시 소프트 경고 (진행은 막지 않음)
- 값이 바뀔 때마다 즉시 저장

**3단계 — 장애 정보** (`src/screens/disability/`) — SYSTEM_SPEC 3-3

- 1단계: 법정 유형 15개(기본 7 + 접힘 8), 체크 시 중증/경증 인라인 라디오
- 2단계: 양상 그룹별 세부 양상. 지체+뇌병변처럼 같은 그룹을 가리키는 유형을
  함께 골라도 질문은 한 번만 나옴. 좌우 구분 항목은 인라인 라디오
- 3단계: 주관식(선택) + 예시 문장 3개 항상 노출
- 유형 해제 시 딸린 정도·양상·좌우 값을 함께 정리

**4단계 — 기기 사양** (`src/screens/deviceSpec/`) — SYSTEM_SPEC 3-4

- 주 기기 7개 항목(운영체제·화면 크기·해상도·주사율·입력장치·시청 거리·오디오).
  확인 방법 안내는 **항상 보이는 캡션**(호버 툴팁 미사용)
- 게임용 보조기기 3택. §3-2의 "평소 보조기기"와 구분되며,
  "평소 쓰는 것을 그대로 씁니다"를 고르면 §3-2 값을 읽기 전용으로 이어받음
- 그 외 게임 기기는 모델명만, 여러 대 추가·삭제 가능

**5단계 이후**는 `PlaceholderScreen` 이 받습니다. 저장된 입력과 진행 로그를
보여주며, 해당 화면이 만들어지면 `App.tsx` 분기에서 빼면 됩니다.

**결과 제출 기반** (SYSTEM_SPEC 3-5) — 컬럼 구성은 테스트가 만들어진 뒤 확정합니다.

| 파일 | 역할 |
|---|---|
| `src/lib/csv.ts` | CSV 직렬화(BOM·CRLF·RFC 4180), 파일명 `{ID}_{YYYYMMDD}_결과.csv` |
| `src/lib/useCsvFile.ts` | `<a download>` 용 Blob URL (합성 클릭 대신 진짜 링크) |
| `src/types/participant.ts` | 고유 ID 형식 `GA11Y-[PAO]\d{2}-\d{3}` 검증 |

CSV 는 Python 표준 파서로 왕복 검증했습니다 — 쉼표·큰따옴표·개행·앞뒤 공백·한글이
섞인 값에서도 9행 완전 일치. BOM 은 Excel 한글 표시에 필요하므로 빼지 마세요.

## 저시력 시인성 기준

SYSTEM_SPEC.md 2절의 기준을 충족한 상태이며, 브라우저에서 실측 검증했습니다.

| 기준 | 현재 상태 |
|---|---|
| 대비 AAA(7:1) 지향 | 어두운 화면 **7.58~19.07:1** / 밝은 화면 **7.32~19.67:1** — 양쪽 모두 AAA, AA 위반 0건 |
| 글자 크기 | 본문 24px, 보조 20px, h1 44px. **20px 미만 없음** |
| 검증 서체 | Pretendard 자체 호스팅 (외부 CDN 미사용) |
| Light/Thin 금지 | 400/500/700만 로드 — 얇은 굵기가 존재하지 않음 |
| 자간·행간 | 자간 `+0.01em`(음수 0건), 행간 1.75 |
| 400% 확대 리플로우 | 320px 폭에서 가로 스크롤 없음 |
| 클릭 타겟 | 48px 이상 |

### 색 역할 예약

색이 겹치면 "지금 어디 있는지"를 색으로 알 수 없으므로 역할을 하나씩 고정합니다.

- **네온 노랑** — 포커스 전용
- **핫핑크** — 필수 표시, 링크, 상호작용 테두리
- **네온 초록** — 체크됨 / 완료
- **주황빨강** — 오류

### 빛 번짐 대응

순수 검정·순수 흰색을 쓰지 않고(근검정 `#0e0f13` + 오프화이트 `#f2f4f8`),
glow 효과를 넣지 않으며, 네온은 좁은 면적에만 씁니다. 번짐 민감도는 사람마다
반대 방향이라 **화면 밝기를 직접 뒤집을 수 있습니다**(기기 설정 / 어두운 화면 /
밝은 화면). 선택은 기기에 저장되고 첫 페인트 전에 반영돼 깜빡임이 없습니다.

### 현재 위치 표시

카드 단위로 강조합니다. 키보드로 들어오면 `:focus-within`이 카드 테두리를
네온 노랑으로, 마우스로 훑으면 `:hover`가 핫핑크로 바꿉니다. 포커스 링은
4px + 3px offset 입니다.

색상 토큰을 수정하면 대비를 **브라우저에서 다시 측정하고**
`src/styles/tokens.css` 주석의 수치를 갱신해야 합니다. 손계산은 믿지 마세요.

## 배포 전 반드시 할 일

`src/data/consentItems.ts` 에서 `⚠️ 확정 필요` 를 검색해 남은 값을 모두 채워야
합니다. 보유·이용 기간, 처리 기관명, 개인정보 보호책임자, 문의처, 제3자 제공
내역이 여기에 해당합니다. **최종 문안은 사내 개인정보 보호 담당자 검토가
필요합니다.**

문안을 실질적으로 개정하면 같은 파일의 `CONSENT_VERSION` 을 올립니다.
그러면 기존에 저장된 동의 기록이 자동으로 무효화되어 재동의를 받습니다.
